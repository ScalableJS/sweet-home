## Главный вывод: поисковик важнее модели

**Твоя гипотеза подтверждена.** Доказательства:

1. **Gemini flash** — мощнее Haiku по параметрам, но упал на rate limit Brave. Результат: 0 польских источников.
2. **Codex gpt-5.4-mini + Tavily** нашёл **6 телефонов** прямо из страниц, ценовой конфликт `3500→5900 zł` из отзыва — данные, которых **нет в сниппетах**. Haiku с Brave этого не видел.
3. Разница не в интеллекте модели — разница в том, **что модель получает на вход**.

```
Brave → заголовок + 200 символов сниппета → модель угадывает
Tavily → полный текст страницы → модель читает
```

## Слабые места Codex + Tavily

- **RU и EN lanes пусты** — Tavily хуже Brave по мультиязычной индексации. Для RU/UK контента в польском контексте Brave ищет лучше.
- **Codex safety filter** отменил 2 запроса из 4 как "procedural violation" — агент-инспектор решил что модель нарушает инструкции. Это баг конфигурации, не проблема Tavily.
- **Нет RU/UA фирм** (by-home, homefamily, flagma) — именно потому что RU lane не отработал.

## Оптимальная архитектура (гипотеза)

Объединить лучшее из двух миров:

```
PL/pl lane  → Tavily (полный текст, цены, контакты)
PL/ru lane  → Brave  (RU-контент в польском контексте)
PL/uk lane  → Brave  (UA-контент в польском контексте)
US/en lane  → Tavily (технические спеки, полный текст)
```

Brave лучше для мультиязычного поиска по языку контента.  
Tavily лучше для извлечения данных с конкретных страниц (цены, контакты, таблицы).
